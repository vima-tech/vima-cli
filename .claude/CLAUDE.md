# 项目元规则

1. **确定性的事走 vima，不手工模拟。**
   编译规格、取证、对账都有命令。手写一份等价产物不会产生事件、不会有证据、进度不涨。
   绕过不被禁止——绕过只是没有收益。

2. **遇到规格矛盾：先定夺，记 ruling，不停下。**
   两份材料打架、需求与代码不一致时，按当前判断继续做，同时把
   「问的是什么 / 选了哪个 / 为什么 / 置信度 / 影响面」记成一条裁定。
   人事后可以推翻，推翻走既有的失效传播，不需要你为它预留回滚。
   不要停下来等人，也不要假装矛盾不存在。

3. **对人只陈述已发生的事实。**
   「做完了」不是证据，证据由系统取证生成。没做的不说成做了，
   没验证的说「没验证」，环境拿不到的数据说「拿不到」——不要填 0 充数。
