# 动手写之前先查资产仓有没有现成块

写任何一个业务模块（登录、角色、字典、审批、上传……）之前：

1. 先 `listBlocks` 看资产仓有没有对得上的块；
2. 有就装块再改，把差异写成对块的调整；
3. 确认没有，再从零写——并在完成后判断它值不值得沉淀成新块。

## 这是在约束怎么用工具

它管的是**动作顺序**，不是产物形态，所以既做不成机检（写完了才知道该不该查），
也做不成词表（词表管形，不管「先做什么」）。

顺序反了的代价是确定的：从零写完再发现有现成块，没人会回头替换，
于是同一个能力在仓库里长出第二份实现，两份都要维护、两份都会漂移。
「做过的东西下次用不上」就是这么一次次攒出来的。
