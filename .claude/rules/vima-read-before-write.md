# 改之前先读，写之前先搜同名概念

- 改一个已有文件前，先完整读它；
- 新增一个概念（字段、状态、错误码、组件、工具函数）前，
  先搜仓库里有没有同名或同义的既有实现。

## 这是在约束怎么用工具

搜与读发生在写之前，写完了再补搜没有意义。它做不成机检，因为「有没有搜过」
不留痕迹；也做不成词表，词表管不了行为顺序。

代价是具体的：不搜就会造出第二个真源（同一个状态两套枚举、同一个校验两处实现），
而第二个真源不会自己消失，它会各自演化，直到某天两边对不上账。

（本条不限定维度：任何层、任何端都成立。）
