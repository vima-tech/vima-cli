# 规则层

这里只放**真的下沉不了**的东西。约束下沉纪律：

```
资产（令牌·词表·块）   ← 最优：写不出非法的东西
  机检规则              ← 次优：写出来了会被指出来
    skill 规程           ← 再次：需要时被读到
      CLAUDE.md 元规则   ← 最后：常驻但只是劝导
```

## 收一条规则前先过两问

1. **能做成机检吗？** 能 → 去写检查，不要写规则。
   （「`:rules` 写了要调 `validate()`」是机检，不是规则。）
2. **能做成词表或令牌吗？** 能 → 去加词、加档，不要写规则。
   （「错误提示不能只打控制台」是 `interaction.vocab.json` 的 `$forbidden`，不是规则。）

两问都是「不能」才留在这里。留下来的通常只有两类：

- **需要人类判断才能应用的**——判据依赖具体情境，写死就会误伤。
- **约束 agent 怎么用工具的**——管的是行为顺序，不是产物形态。

## 写法

frontmatter **只允许维度键** `layer` / `side` / `app` / `block`，写错一个键会当场报错——
被静默忽略的限定词会让规则从「只在小程序生效」悄悄变成「处处生效」。
不限定某个维度就不要写这个键。

规则 id 从文件名推导（去掉 `.md`），不设 id 字段：同一件事两个真源必然有对不上的一天。

## 规则只增不减是病

`deadRules(rules, allDims)` 会把「在维度全集里跑遍所有组合、一次都没被选中」的规则捞出来。
死规则要么删掉，要么修正它的维度声明。规则层膨胀到没人看得完，等于没有规则。
