# 小程序端先认宿主边界，再谈实现

登录、支付、分享、定位、文件、包体大小——这些在小程序端由宿主说了算，
不是「H5 怎么做小程序照做」。

1. 动手前先确认宿主提供什么、限制什么；
2. 宿主不支持而需求要 → 按 `contract-gap` 处置（多数时候是 `narrow-scope`
   或 `hide-affordance`），不要用 H5 的做法硬套；
3. 宿主能力的调用时机（如登录态换取）属于契约的一部分，要写进 L1，
   不能只活在前端代码里。

## 为什么留在规则层

宿主能力清单会变，且各宿主不同，硬编码成机检很快就会误报；
它也不是版面或交互问题，词表里没有它的位置。
判断「这个能力宿主到底给不给」需要人去查当下的宿主文档。
