# 业务块

一个块 = 一个目录 `blocks/<set>/<name>/`。没有清单文件，目录结构就是注册表——
加一个块只是丢一个目录进来，`listBlocks` 立刻看得见，代码一行不改。

## 四层

| 层 | 文件 | 装什么 | 判据 |
|---|---|---|---|
| L1 契约 | `L1.contract.md` | 数据模型 · 端点 · 错误码 · 权限点 | 前后端都要照着它写，**它是这个块唯一的对账基准** |
| L2 后端 | `L2.backend.md` | 目录结构 · 分层职责 · 实现要点 | 可以是占位说明，但目录与职责必须确定 |
| L3 前端行为 | `L3.frontend.md` | 状态机 · 调用序列 · 校验规则 · 错误处置 | **纯逻辑无视觉**：不出现颜色、间距、字号、组件库名 |
| L4 视觉 | 不提供 | —— | 见下 |

层文件命名 `L<n>.<slug>.md`，**必须在块根，每层至多一个**。
两个文件争同一层就是两个真源，`readBlock` 会直接报错。

## L4 默认不提供

资产仓不带视觉层。理由：

- 视觉由令牌（皮）+ 版面词表决定，块自带一套视觉等于绕过皮，换皮就换不动了；
- 块自带视觉会和 UI 设计工序抢真源，同一个页面出现两份互相矛盾的视觉规定，
  最后谁也不敢改。

所以 `readBlock` 的返回里 **L1–L3 恒有键（缺失为 null），L4 只在真的存在时才有这个键**——
「没有 L4」是一条决定，不是一处遗漏，用键的有无表达，消费方不必猜 null 是哪种意思。

块要表达自己的版面与交互意图时，在 L3 里**引用词表的词**（如 `layout:split-master-detail`、
`interaction:contract-gap:block-and-declare`），不要描述它长什么样。

## block.json

只放元信息、适用端、依赖。**不重复 L1 里已有的东西**——端点数、权限点清单都在 L1，
在 block.json 再抄一份，就等着有一天两边对不上。

## 空的 set 目录

`blocks/common/`、`blocks/wechat/` 目前只有 `.gitkeep`。
占位是故意的：**不为了凑数写假块**。假块比没有块更贵——它会被装进项目，
然后有人花时间去改它，最后发现里面本来就没有内容。
