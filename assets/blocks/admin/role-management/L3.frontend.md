# L3 前端行为 · 角色与权限管理

**纯逻辑，无视觉。** 这里不出现颜色、间距、字号、组件库名。
要表达「长什么形」只引词表的词；具体长什么样由令牌（皮）与 UI 设计工序决定。

## 页面与外壳

| 页面 | `ia:page-kinds` | `layout:shells` | 区域 | 主区块 |
|---|---|---|---|---|
| 角色列表 | `list` | `sidebar-main` | `page-title` · `toolbar` · `filter-bar` · `content` | `data-table` |
| 角色表单（新建/编辑） | `form-create` / `form-edit` | 承载于 `drawer` | `drawer` · `footer-bar` | `form-single` |
| 权限授权 | `settings` | 承载于 `drawer` | `drawer` · `footer-bar` | `tree-panel` |
| 用户分配 | `settings` | 承载于 `modal` | `modal` · `footer-bar` | `transfer` |

- 密度 `layout:density:standard`；栅格 `layout:grids:col-1`。
- 入口：菜单 `ia:entry-points:menu` → 列表；行内 `ia:entry-points:drawer-from-row` → 表单/授权；
  按钮 `ia:entry-points:modal-from-button` → 用户分配。
- 跳转：本块内部全部是 `ia:transitions:drawer` / `modal`，**不发生路由跳转**；
  筛选与分页按 `interaction:filter-persistence:url-query` 同步到地址。

## 交互范式选定（每个涉及的 group 必须选定一个）

| group | 选定 | 为什么是它 |
|---|---|---|
| `form-validation` | `on-blur-then-live` + `async-on-blur`（仅 code / name 唯一性） | 格式错误即时可纠；唯一性只有服务端知道 |
| `error-feedback` | `field-inline` + `form-summary` | 字段级错误必须落到字段；抽屉内可能滚动，需顶部汇总 |
| `empty-state` | `first-run` / `no-result` / `no-permission` 三态各写各的 | 空态成因不同，说辞与出口不能混 |
| `loading` | `skeleton`（列表首屏）· `inline-spinner`（翻页/筛选）· `button-pending`（所有写操作） | |
| `load-failure` | `retry-inline`（权限树、用户列表）· `retry-page`（角色列表主数据） | |
| `row-action-visibility` | `hide-forbidden`（无权限点）+ `disable-with-reason`（内置角色） | 权限是身份问题，内置是状态问题——两者处置不同 |
| `destructive-confirm` | `modal-confirm`（删除角色，不可逆） | 删除不可逆且影响他人权限 |
| `success-feedback` | `stay-and-refresh`（抽屉关闭 + 列表局部刷新） | 维护类操作连续进行，不该跳走 |
| `unsaved-changes` | `warn-on-leave`（关闭抽屉/弹窗前） | 授权树勾选量大，误关代价高 |
| `duplicate-submit` | `disable-until-response` | 写操作最低要求 |
| `pagination` | `paged` | 管理型表格要能核对总数 |
| `permission-degradation` | `hide-entry`（无 `system:role:menu`）· `read-only-view`（只有 view 无写权限） | |
| `contract-gap` | `block-and-declare` | 本块契约完整；若项目侧缺端点，按默认档停手登记，不得就地补 |

## 状态机

### 列表页

```
idle ──load──▶ loading ──ok──▶ ready ──empty?──▶ empty(first-run | no-result)
                  │                  │
                  └──fail──▶ failed ─┴─retry──▶ loading
ready ──filter/paginate──▶ refreshing ──ok──▶ ready
                                       └fail──▶ ready + inline-banner（保留旧数据，见下）
```

`refreshing` 失败时**保留旧数据并挂提示**（`load-failure:stale-with-notice` 的同族处置），
不清空表格——清空会让用户以为「筛出来没有」，那是在说谎。

### 表单抽屉

```
closed ──open(create)──▶ editing(pristine)
closed ──open(edit,id)──▶ loading ──ok──▶ editing(pristine)
                                  └fail──▶ loadFailed（抽屉内 retry-inline）
editing(pristine) ──change──▶ editing(dirty)
editing(dirty) ──submit──▶ submitting ──ok──▶ closed + 列表刷新
                                       ├─validationError──▶ editing(dirty) + field-inline
                                       └─ROLE_STALE──▶ editing(dirty) + inline-banner（提示重载）
editing(dirty) ──close──▶ confirmDiscard ──confirm──▶ closed
editing(pristine) ──close──▶ closed        // 无改动不打扰
```

`submitting` 期间：提交按钮 `button-pending`，抽屉不可关闭。

### 授权抽屉

```
closed ──open(roleId)──▶ loading(并行取 权限树 + 已授权 codes)
loading ──both ok──▶ ready(checked = 已授权 ∩ 树中存在的 code)
loading ──任一 fail──▶ loadFailed（retry-inline，两个请求各自可重试）
ready ──toggle──▶ ready(dirty)
ready(dirty) ──submit──▶ submitting ──ok──▶ closed
                                     └─PERMISSION_CODE_UNKNOWN──▶ ready + inline-banner（提示刷新权限树）
```

**`已授权 ∩ 树中存在`** 这一步不能省：权限点被下线后，旧授权里会残留不存在的 code，
直接勾选会静默丢失（提交时被后端拒绝，用户不知道为什么）。
残留 code 必须在 `inline-banner` 里列出来，告诉用户「这几个权限点已下线，保存后将被移除」。

## 调用序列

1. **进入列表**：`GET /roles`（带 URL 上的筛选与分页）。
   并行取当前用户权限点集合（若外壳未提供）——它决定哪些行操作渲染。
2. **打开编辑**：`GET /roles/{id}`。不用列表行里的数据直接填表——
   列表返回的是摘要，字段不全，用它填表会把没返回的字段提交成空。
3. **提交表单**：`POST` 或 `PUT`，携带 `updatedAt`。成功后关闭抽屉并**只刷新列表当前页**。
4. **打开授权**：`GET /permissions/tree` 与 `GET /roles/{id}/permissions` 并行；两者都到齐才渲染。
5. **提交授权**：`PUT /roles/{id}/permissions`，提交**全量** code 列表（含未变化的）。
6. **打开分配**：`GET /roles/{id}/users` 取已选，候选用户走用户检索接口（分页 + 关键词）。
7. **提交分配**：`PUT /roles/{id}/users`，全量 userId 列表。

## 前端校验规则

| 字段 | 规则 | 时机 |
|---|---|---|
| `code` | 必填；`^[a-z][a-z0-9_]{1,31}$`；编辑态不可改（不渲染为可输入） | 失焦 + 唯一性远程校验 |
| `name` | 必填；1–32 字符；首尾空白自动去除后再校验 | 失焦 + 唯一性远程校验 |
| `dataScope` | 必选 | 提交时 |
| `deptIds` | `dataScope=custom` 时必填非空；切到其它值时**清空**（`interaction:field-dependency:reset-downstream`） | 联动即时 |
| `remark` | ≤ 200 字符，超出即时提示剩余 | 输入时 |

前端校验**不替代后端校验**。唯一性远程校验失败（请求本身失败，不是校验不通过）时，
不阻止提交，交给提交时的服务端结果——把网络抖动变成「无法提交」是过度拦截。

## 错误处置

- 字段级错误码（见 L1）一律 `field-inline` 落到对应字段；映射表在实现里必须是一张**显式表**，
  不要靠错误消息文本猜字段。
- 非字段级错误 `inline-banner`，文案说明「发生了什么 + 现在能做什么」。
- 401/403：交给外壳统一处置，本块不自行跳登录页——每个块各跳一次会互相打架。
- 任何请求失败都必须有用户可见的交代。**只打控制台是缺陷**
  （`interaction.vocab.json:error-feedback:$forbidden:console-only`）。

## 权限点 ↔ 界面元素（成对）

| 权限点 | 绑定的界面元素 | 缺失时 |
|---|---|---|
| `system:role:menu` | 菜单项「角色管理」 | `hide-entry` |
| `system:role:view` | 列表页可访问 | `no-permission` 空态 |
| `system:role:create` | 工具条「新建」 | `hide-forbidden` |
| `system:role:update` | 行「编辑」「启用/停用」 | `hide-forbidden` |
| `system:role:delete` | 行「删除」 | `hide-forbidden` |
| `system:role:grant` | 行「授权」 | `hide-forbidden` |
| `system:role:assign` | 行「分配用户」 | `hide-forbidden` |

内置角色（`builtin=true`）：编辑与删除按 `disable-with-reason` 禁用并说明「内置角色不可修改」，
**不是隐藏**——隐藏会让用户以为自己没权限，跑去申请一个并不存在的权限。
