# L1 契约 · 角色与权限管理

本层是这个块唯一的对账基准。前后端都照它写，出现分歧改这里，不在任何一侧就地约定。

## 数据模型

### role 角色

| 字段 | 类型 | 约束 | 说明 |
|---|---|---|---|
| id | string | PK | 系统生成 |
| code | string | 唯一，`^[a-z][a-z0-9_]{1,31}$` | 创建后不可改（已授权数据引用它） |
| name | string | 必填，1–32 字符，同租户内唯一 | 显示名，可改 |
| dataScope | enum | `self` \| `dept` \| `dept_and_below` \| `all` \| `custom` | 取值与 `ia.vocab.json` 的 `permission-kinds:data-scope` 对齐 |
| deptIds | string[] | `dataScope=custom` 时必填且非空，其余情形必须为空 | 自定义数据范围 |
| builtin | boolean | 只读 | 内置角色不可删、不可改 code |
| status | enum | `enabled` \| `disabled` | 停用的角色不参与鉴权 |
| remark | string | ≤ 200 | |
| createdAt / updatedAt | datetime | 只读 | |

### permission 权限点（只读，由各块声明后汇总）

| 字段 | 类型 | 说明 |
|---|---|---|
| code | string | 形如 `system:role:create`，三段式 `<模块>:<对象>:<动作>` |
| name | string | 显示名 |
| kind | enum | `menu` \| `page` \| `action` \| `field`（与 `ia.vocab.json:permission-kinds` 同集合，`data-scope` 不在此表，它是角色的字段） |
| parentCode | string \| null | 构成权限树 |

### role_permission / user_role

两张关联表，均为 `(roleId, permissionCode)` / `(userId, roleId)` 唯一。
授权与分配都是**全量覆盖**语义，不做增量补丁——增量语义会让「取消勾选」变成不可表达。

## 端点

| 方法 | 路径 | 权限点 | 说明 |
|---|---|---|---|
| GET | `/api/system/roles` | `system:role:view` | 分页，支持 `keyword` / `status` |
| GET | `/api/system/roles/{id}` | `system:role:view` | 详情 |
| POST | `/api/system/roles` | `system:role:create` | 创建 |
| PUT | `/api/system/roles/{id}` | `system:role:update` | 更新（`code`、`builtin` 不接受） |
| DELETE | `/api/system/roles/{id}` | `system:role:delete` | 删除，内置角色或仍有用户在用时拒绝 |
| PUT | `/api/system/roles/{id}/status` | `system:role:update` | 启用/停用 |
| GET | `/api/system/permissions/tree` | `system:role:view` | 权限点全树 |
| GET | `/api/system/roles/{id}/permissions` | `system:role:view` | 该角色已授权的权限点 code 列表 |
| PUT | `/api/system/roles/{id}/permissions` | `system:role:grant` | **全量覆盖**授权 |
| GET | `/api/system/roles/{id}/users` | `system:role:view` | 该角色下的用户，分页 |
| PUT | `/api/system/roles/{id}/users` | `system:role:assign` | **全量覆盖**分配 |

分页出入参、包裹结构、鉴权头沿用项目级 API 约定，本块不另立一套。

## 错误码

| code | HTTP | 含义 | 前端处置（引 `interaction.vocab.json`） |
|---|---|---|---|
| `ROLE_CODE_DUPLICATE` | 409 | 角色编码已存在 | `error-feedback:field-inline` 落到 code 字段 |
| `ROLE_NAME_DUPLICATE` | 409 | 角色名已存在 | `error-feedback:field-inline` 落到 name 字段 |
| `ROLE_BUILTIN_IMMUTABLE` | 403 | 内置角色不可改/不可删 | 该行动作按 `row-action-visibility:disable-with-reason` 预先禁用；仍收到此码则 `error-feedback:inline-banner` |
| `ROLE_IN_USE` | 409 | 角色下仍有用户，不可删 | `error-feedback:inline-banner`，附「查看使用该角色的用户」入口 |
| `ROLE_NOT_FOUND` | 404 | 角色不存在（多为并发删除） | `error-feedback:page-error` + 回列表 |
| `PERMISSION_CODE_UNKNOWN` | 400 | 提交了不存在的权限点 | `error-feedback:inline-banner`，提示刷新权限树后重试 |
| `DATA_SCOPE_DEPT_REQUIRED` | 400 | `custom` 范围未选部门 | `error-feedback:field-inline` 落到部门选择器 |
| `ROLE_STALE` | 409 | 提交时角色已被他人改动 | `error-feedback:inline-banner` + 提示重新加载（乐观并发，见下） |

并发：更新与授权请求携带 `updatedAt` 作为并发标记，不一致返回 `ROLE_STALE`。
不做静默后写覆盖——后写覆盖会让「谁把我的授权改回去了」永远查不出来。

## 权限点（本块声明）

| code | kind | 绑定 |
|---|---|---|
| `system:role:menu` | menu | 菜单项「角色管理」 |
| `system:role:view` | page | 列表页与详情 |
| `system:role:create` | action | 新建 |
| `system:role:update` | action | 编辑、启停 |
| `system:role:delete` | action | 删除 |
| `system:role:grant` | action | 授权权限点 |
| `system:role:assign` | action | 分配用户 |

**成对纪律**：`system:role:menu` 必须绑定到菜单项，其余六个必须各自被至少一处页面或行操作引用。
孤儿权限点与无权限点的菜单项都是缺陷，两边都要能被查出来。
