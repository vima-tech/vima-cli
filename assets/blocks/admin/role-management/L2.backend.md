# L2 后端 · 角色与权限管理

**本层是占位说明 + 目录结构，不含完整实现。** 装块时按此结构落文件，实现照 L1 契约写。

## 目录结构

```
<后端模块根>/system/role/
  RoleController          端点映射、入参校验、权限点注解，不含业务逻辑
  RoleService             业务规则（唯一性、内置角色、在用校验、并发标记）
  RoleGrantService        授权与分配两个全量覆盖动作，单独一个服务
  RoleRepository          role 表读写
  RolePermissionRepository / UserRoleRepository
  dto/                    RoleCreateReq · RoleUpdateReq · RoleQuery · RoleView · GrantReq
  RoleErrors              L1 错误码常量的唯一定义处
```

## 分层职责

- **Controller** 只做协议层的事：解析、校验形状、绑权限点、映射错误码到 HTTP。
  不写 if 业务判断——业务判断跑进 Controller，Service 就没法被单测。
- **Service** 持有全部业务规则。每条规则对应 L1 里的一条约束，一一对得上。
- **Repository** 只做数据访问。

## 实现要点（这些坑装块时会踩）

1. **全量覆盖授权用「先删后插 + 同一事务」**，不要做 diff 增量。
   增量语义下「取消勾选最后一个权限」会退化成空提交，无法与「没改」区分。
2. **`code` 创建后不可改**：`RoleUpdateReq` 里根本不要有这个字段，
   而不是收下再忽略——收下再忽略会让调用方以为自己改成功了。
3. **停用角色不参与鉴权**：鉴权时过滤 `status=enabled`，否则停用形同虚设。
4. **删除前检查在用**：`ROLE_IN_USE` 要带上占用数量，前端才能给出有意义的提示。
5. **并发标记**：更新与授权都比对 `updatedAt`，不一致返回 `ROLE_STALE`。
6. **内置角色**：`builtin=true` 的记录在 Service 层统一拦截，不靠前端隐藏按钮保证。
   前端隐藏是体验，后端拦截是正确性，两者都要有。

## 测试落点

- Service 单测覆盖上述 6 条规则各自的正反例；
- 授权接口的并发覆盖用例（两次提交携带同一 `updatedAt`，第二次必须失败）。
