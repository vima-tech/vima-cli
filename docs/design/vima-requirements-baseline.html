vima 需求基线

需求

Requirements

R1从零散物料产出能跑的系统

起点大概率什么都没有——只有截图、旧代码、SQL、零散文档，且它们互相矛盾、互相取代。要能整理成结构化需求，再一路做成系统。

判据冷读通过——新起一个 agent，只给它规格，看它能否开工、有无追问
裁定物料形式不限（PRD / SDD / PACT 皆可）· 不要求完整继承 PACT · 冷读作度量不作闸门（跑、记分、展示，不拦）
边界「这条需求对不对」不做程序化确认——它由人与 AI 讨论得出，默认人已审核。系统只记录出处（供 R6 回溯），不质疑内容
实证上轮物料 112 文件 3.6MB，其中 76 张 PNG；SDD 只含 40/85 张表、API 覆盖 206/335 端点、原型覆盖 43/61 页且视觉与结构双失效
R2观测平台最高优先

一个统一的观测面，回答五类问题。五类必须共用一个数据底座——分开做必然重演「事实散在五处、join 靠人脑」。

问的是要看到
这条做对了吗、凭什么每条需求的证据与强度（分级——每条自己声明需要多强）
整体做到哪、能交付吗真实进度（不把「自称做完」计入）与可交付性判定
过程怎么走的、谁做的历史回放 + Agent 行为（跑多久、读什么、产出什么）
花了多少token 与时长，分摊到环节 / 代理 / 任务
哪些是 AI 替我定的裁定台账，含置信度与影响面，可二次裁决
判据五类问题在同一个界面上都能回答，且数据同源可对账
裁定形态 web trace UI · 受众为自己看 + 对外展示交接 · 「每条需求必须有可执行的验收方式」归入本条（没有验收方式就产生不了证据，这一格永远是空）· 裁定须带置信度与影响面
范围本轮证据阶梯止于「跑了命令且绿」——「真跑一遍界面」这一档不建采集设施（见「已接受的风险」）。视觉正确性改由实现阶段的设计稿事前约束，见 R7
实证上轮走验收链路的 21 个任务通过率 100%，没走的 87 个是 18%，而唯一信号是 doctor 一条 warn
R3中途改需求，影响面是算出来的

改一处，能拿到「还有哪些地方跟着失效」的清单，不靠人估。二次裁决走同一条链路。

判据改完的标志是失效清单清空，不是人觉得改完了
R4 · 真实进度与可交付性 —— 已并入 R2
R5并行加速
判据实际并发数可观测，且与计划并发数可对账
实证上轮 20 个验收代理把 337 分钟压进 78 分钟（4.3×），但分波派发浪费约 3.5 倍——理论上限是 20×
R6出问题能定位到是哪一步错的
判据任意症状能回溯到第一条证据不足或与上游矛盾的地方
注意R1 修正后，回溯链要一路通到「当初从物料里就理解错了」与「熔合门当时怎么裁的」
R7产出企业风格化产品，风格统一可控

骨相统一（结构与交互范式写死）、皮相可变（颜色字体圆角项目级可换）。四层全管：

层骨/皮约束形态
信息架构骨导航结构 · 页面间跳转必须显式声明 · 权限点↔菜单成对
交互骨范式词表：校验 / 错误反馈 / 空态 / 加载失败 / 行操作显隐，各若干种选一，不许自由发挥
版面骨版面词表 + 区块词 + 骨架组件
令牌皮阶梯定义 + 禁裸值；阶梯本身可整体替换
判据四层各有封闭词表或阶梯 · 骨架自身也满足，不得豁免自己
裁定词表宁宽勿窄，尽量留足灵活性——风险不是词表大而是不封闭。支持持续扩展：缺词不阻塞，AI 可先用，但须记录进观测平台由人二次裁决收编。初值由既有项目实际写法归一化统计得出，不拍脑袋
视觉落地实现阶段由 Claude Design 产出设计稿作为事前约束——把「做完再验」换成「照着稿做」，从验形挪到定形，成本低得多。两个档位：高保真稿（贵，视觉完整）与框线图（省，只管结构与信息层次）。框线图恰好对应骨相，皮相由令牌阶梯自动管，是默认档
实证有词表的层可机检（区块对账成立），没词表的层不可机检：89.8% 页面错误提示静默、12/45 页校验形同虚设、同一契约缺口四种处置；反向代价也实测过——48 页里 19% 因词表不够被迫降级
R8 · 全过程可观测 + web trace UI —— 已并入 R2
R9存量项目接管

两种都要：接管从未用过 vima 的陌生代码库 + 升级旧 vima 项目。

判据陌生库接管后能产出完整命题图，且反推的命题来源可标最高档、验证强度不得自动继承
理由这个区分不做，接管等于把既有缺陷追认成规格——「读得到空数据」「规则零执行点」「契约字段恒空」全会被反推成「需求本来就这样」
R10 · 成本可观测 —— 已并入 R2
R11可复用业务块库

成套的业务功能块，按端分集，持续扩展。起点三类只是起点不是全集：后台管理（配置 / 角色 / 菜单 / 人员 / 部门 / 字典 / 日志）· 微信生态（登录 / 支付 / 分享 / 订阅消息）· 通用能力。

它的价值不是省 token，是把这些问题从命题空间里整个移除——已经被验过的东西不需要再命题、再取证、再验收。

分层L1 契约 · L2 后端 · L3 前端行为（纯逻辑无视觉）跨项目稳定；L4 视觉默认不提供——带了会与 UI 设计代理冲突
判据加一个块不需要改内核 · 块不含 L4 也能被完整消费 · 拿错端的块是机检项
收录同时满足「语义跨项目稳定」+「实现有标准解」。反过来说更清楚：两个不同行业的项目都会用到它、且用法基本一致。业务特有的不进
裁定L1–L3 是骨、L4 是皮——这是 R7 原则往上提了一层，不是新规则

约束

Constraints — 不是需求，但约束所有设计

C1

执行者会偷懒、会自称完成。

机制必须假定这一点。上轮实证：43 个任务都写了「Service 层单元测试」验收项，实际覆盖 0/58，而 mvn test 恒绿

C2

防过度设计。每处设计能反查到 R1–R11 的某一条。

反查不到 = 未授权复杂度。约束别扩面 · 抽象别提前 · 字段表别镀金

C3

文档可读、可 diff、可 code review。

现有形态最值得保的性质。任何索引/图都必须是可随时重建的派生物，不能反过来当真源

C4

设计与开发阶段不阻塞。需要人裁定的一律先由 AI 定夺并记录，人事后推翻。

前提是记录够硬：显式落盘（不能写在代码注释里）· 可见（观测平台）· 可推翻（触发失效传播）。上轮反面案例：builder 自行裁定设备状态枚举，理由写在 types.ts 注释里，导致三条写路径 100% 被拒——问题不在自行裁定，在斩了没奏

明确排除

Out of scope — 排除是决定，不是遗漏

项理由
排除 多人多会话协作当前范围是「一个人 + 一个会话内的多个子代理」。纳入会把并发控制升级成真正的分布式问题
排除 业务块的版本与兼容「支持不断扩展」指的是注册表开放性；版本管理是另一件事，未提出即不做

裁定台账

Rulings — 对齐过程中做出的决定与理由

涉及决定理由
R1不要求完整继承 PACT判据是「产出的物料能让 AI 稳定工作」，形式不限。PACT 已归档、继任者即 vima，本质是继承边界划定
R1熔合门自行定夺多来源矛盾由 AI 裁定并记录，不停下来问人。配 C4 的三条硬要求
R1冷读门降为度量与 C4 不阻塞冲突。跑、记分、展示，不拦
R2吸收原 R4 / R8 / R10四者是同一件事的四个面，共用一个底座是需求而非优化
R2「需求必须有可执行验收」归入它不是独立门禁，是观测平台的前置条件——没有验收方式就产生不了证据
R2裁定须带置信度与影响面展示的必要精度。200 条流水账人不会看；同理于「永远消不掉的告警会训练人忽略整张表」
R7词表宁宽勿窄风险不是词表大而是不封闭；10 个词和 40 个词可机检性相同，而窄词表会逼出逃生口
R11视觉层默认不提供真实前端会与 UI 设计代理冲突。分层后设计代理消费 L3 行为契约、自产 L4
R2 · R7不做「真跑界面」这一档本轮成本不划算。视觉转由 Claude Design 事前约束，框线图为默认档；行为仍靠跑测试覆盖。风险记为 AR-1
R1需求正确性不做程序确认由人与 AI 讨论得出，默认已审核。系统只记录出处供回溯，不质疑内容
R7词表按推荐取宽留足灵活性空间；持续扩展，新建议进观测由人二次裁决
全局两条生长通道：扩词 · 沉淀形状相同——缺什么不拦路，但缺这件事必须留痕；累积的留痕就是该往哪长的证据

已接受的风险

Accepted risk — 裁定为不做，不等于问题消失

原「尚未解决」三条本轮全部有了处置，但性质不同：一条是风险接受，一条是范围排除，一条是已裁定。混为一谈会让下一轮的人以为问题解决了。

AR-1运行期行为正确性缺一档证据已接受

「真跑一遍界面」这一档本轮不建采集设施。视觉正确性改由 Claude Design 的设计稿事前约束覆盖——从验形挪到定形，成本低得多。

代价设计稿约束的是「长得对不对」，管不了「行为对不对」。上轮那批缺陷设计稿一个都看不出来：12/45 页 :rules 写了不调 validate()（类型正确、语法正确、构建全绿、行为错误）· 89.8% 页面错误提示对用户静默 · 主入口因解包路径写错而打不开
缓解E3 保留且必须加强——R7 交互层判据仍是「跑测试证明校验真的拦住提交」。放弃的是最上面那一档，不是所有运行时验证。若 E3 也不做，R7 交互层就落空了
复议当出现「测试全绿但用户说用不了」的实例时，重新评估

本轮处置

Resolutions — 原未解三条的去向

原问题处置去向
最强证据很贵风险接受本轮不做 → AR-1；视觉转由 Claude Design 事前约束（R7），行为仍靠 E3
需求对不对无机械证据范围排除不做程序化确认 → 写入 R1 边界。人与 AI 讨论得出，默认已审核；系统只记录出处供回溯
词表初值已裁定宁宽勿窄、留足灵活性 → 写入 R7 裁定；支持持续扩展，新建议记录进观测由人二次裁决

三条各归其位后，当前无未决项。新出现的未决项应追加进上一节，而不是留在讨论里。
