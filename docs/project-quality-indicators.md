## Q-01 角色导航千人千面（以人为本的菜单编排）

### 要求

多角色业务系统的侧栏菜单，**不允许所有角色共用同一套分组结构**。

每个角色的菜单分组、分组命名、组内顺序，都必须按**该角色的真实工作习惯**单独编排：
分组要对应这个岗位脑子里的分区，组内顺序要对应他一天里的动作顺序。
「一棵共享菜单树 + 按角色过滤条目」不满足本条——那只做到了千人千面里的「面不同」，
没做到「排布也不同」，结果是每个角色都在别人的骨架里找自己的东西。

同时必须满足：**角色蓝图只决定「怎么排」，不决定「能不能看」**。
可见性由页面自身登记的 `roles` 与后端鉴权决定，蓝图排错只会难用，不会越权。

### 指标（可判定）

| 指标 | 判定 |
|---|---|
| Q-01.1 分组差异度 | 任意两个角色，若其可见页面集合不同，则二者的**分组标题序列**必须不同。全系统不得存在「所有角色分组完全一致」的情况。 |
| Q-01.2 无死链 | ∀角色 r，∀蓝图中的路径 p：`r ∈ PAGES[p].roles`。（排了却点不进去 = 被守卫弹回） |
| Q-01.3 无孤儿页 | ∀角色 r，∀页面 p：`r ∈ PAGES[p].roles` ⇒ p 必须出现在 r 的蓝图里。（有权限却无入口） |
| Q-01.4 无空壳组 | 任何渲染出来的分组条目数 ≥ 2；只有 1 条的分组必须退化为一条直达菜单，不套折叠壳。 |
| Q-01.5 首屏可达 | 每个角色使用频次最高的那个页面，必须位于侧栏**第一组之内且无需滚动**即可见。 |
| Q-01.6 单一命名 | 同一页面在所有角色下的菜单标题**完全一致**，且与该页路由 `meta.title`（顶栏页名/页签名）一致。角色差异只允许由**组名**表达。 |
| Q-01.7 视角不改权 | 若提供「角色视角切换」，切换只改变导航渲染；路由守卫与接口鉴权始终按用户角色**全集**判定，切换前后可访问的 URL 集合不变。 |
| Q-01.8 版面同源 | 页面级的角色化版面（如工作台的快捷动作/指标卡）必须与侧栏取**同一个**当前角色，不得各自判定。 |

### 反例

- ❌ 药师全系统只有 2 个可用页，却仍呈现为 7 个分组的骨架，其中 5 组是空的或只剩一条。
- ❌ 护士一上班第一件事是「每日执行清单」，而它被排在「住院长嘱」组的第三项。
- ❌ 同一个 `/workflow`，药师菜单里叫「处方审核」，顶栏页名却是「诊疗流程」——用户以为点错了。
- ❌ 切换到「护士视角」后管理员访问 `/system/users` 被弹回登录页（把视角当成了降权）。
- ❌ 侧栏已切到护士菜单，工作台仍显示「营养筛查 / 开处方 / 处方审核」三枚按钮。

### 自检方法

1. **静态自检（必须可脚本化）**：在菜单配置模块内提供一个纯函数，遍历「角色 × 页面」两个集合，
   输出 Q-01.2 / Q-01.3 / 路径拼写错误三类问题，空数组即通过；开发环境启动时自动跑一次并告警。
   —— 这三类问题人肉逐角色点页面才能发现，必须自动化。
2. **实测（每个角色各一次）**：用无头浏览器逐角色登录（多角色账号则逐个切换视角），
   断言：分组标题序列、条目数、首组首条；并对 Q-01.7 做一次「切换后直接访问原 URL 仍可达」的验证。
3. **人审**：Q-01.1 的「分组是否真的贴合岗位」与 Q-01.5 的「最高频页面是哪个」无法脚本判定，
   须由懂业务的人逐角色确认一次，结论写进项目文档。

### 参考实现

Sustain 临床营养管理系统（IA v4.0，2026-08-16 落地）：

- `sustain-web/src/config/menu.js`
  - `PAGES`：页面登记表 = 唯一真源（title / icon / roles / perm / featureFlag），`roles` 与路由 `meta.roles` 逐字等价。
  - `ROLE_MENUS`：每角色一套分组蓝图，只写 `{ title, items: [path] }`。
  - `auditRoleMenus()`：Q-01.2 / Q-01.3 / 拼写错误的静态自检，开发环境启动时执行。
- `sustain-web/src/stores/auth.js`：`activeRole` 仅影响菜单渲染；`currentRole` 校验持久化值仍在本人角色内。
- 角色切换入口置于侧栏左下角用户卡下拉，单角色用户不渲染该入口。

落地后实测（2026-08-16，六个角色各一次无头浏览器实测；条目数为运行时过滤后的实际渲染数，
系统内已有 `menu_hidden` 全局隐藏 3 条）：

| 角色 | 分组数 | 条目数 | 分组序列 |
|---|---|---|---|
| 营养医师 | 7 | 28 | 今日工作 · 门诊诊疗 · 住院营养 · 院外随访 · 费用结算 · 营养资源 · 临床字典 |
| 营养师 | 3 + 1 直达 | 13 | 今日工作 · 营养评估 · 院外随访 ·（营养膳食直达） |
| 药师 | 1 + 1 直达 | 3 | 处方审核 ·（工作台直达） |
| 临床医生 | 1 + 2 直达 | 4 | 营养会诊 ·（工作台、患者管理直达） |
| 护士 | 2 | 6 | 今日执行 · 床旁作业 |
| 系统管理员 | 7 + 1 直达 | 27 | 运营总览 · 组织与权限 · 临床字典 · 基础数据 · 营养商城 · 费用结算 · 集成运维 ·（内容运营直达） |

其中最能说明本条要求的一处对比：**护士与营养医师的顺序正好相反**——

营养医师是「先看今天有谁，再进流程」（患者管理在第一组）。同一批页面，两种排法。
