# 设计优先（Design-First）前端体系 —— vima-cli 设计方案 v1

> 创建日期：2026-08-14 · 更新日期：2026-08-14（补 §12 质量链；§13.1 框架处置；§4.3 改三层供给·组件降位 D-DF-11）
> 定位：**理想态设计，刻意不受既有实现形态约束**（迁移与兼容另行设计，见 §13 说明）。
> 供用户评审；评审通过后作为 AI 完善 vima-cli 的输入。
> 事实依据：`frontend-layout-quality-assessment.md`（68 页逐文件量测 + 六轮专题评估，
> 全部数字来自最终版检测命令）。本文不重复论证，只引用结论。

---

## 0. 一句话

**把「设计」从每页的即兴发挥，升格为与契约同级的真源产物**：
一门可机检的页面设计语言（PDL）+ 一套数据化的设计系统（DS）+ 三级保真验证链。

当前体系里，实体有 spec 第二章、接口有契约、业务规则有 `vima:rules`、页面有区块清单——
**唯独「怎么排、给谁看、怎么读」没有真源**。版面是最后一个没有真源的东西，
所以它是唯一一个每页都要重新即兴发挥的东西。本方案补上第五个真源。

---

## 1. 要解决的问题（实测锚点）

五个症状，同一个根：

| # | 症状 | 实测 |
|---|---|---|
| S1 | 凌乱、不紧凑 | 59/68 页共 **8572 行**页面私有样式；间距 **36 种**取值（令牌只有 5 档）、字号 14 种 |
| S2 | 撑不满 / 溢出 / 被裁 | 骨架契约已修复但**零守卫**，页面私有样式可随意推翻 |
| S3 | 表达不出真实版面 | 词表 7 词，**19% 页面被迫降级**，且全是核心页；抽屉、页签加载、行内编辑等交互无法声明 |
| S4 | 线框古板、看不出设计 | 渲染器只有 **5 个词**高保真，`cards/tabs/toolbar/search` 一律灰盒；三列渲染出来是三个一样的灰盒 |
| S5 | 空间浪费在琐碎处 | **17 个页面为一个按钮独占一条 70px 横带**（≈首屏高度的 7.4%）；41 页有 toolbar，78% 只有 1–3 个按钮 |

根因链（每个症状都是它的一个投影）：

```
设计判断无处声明（无语言）
  → AI 想清楚了也写不下来          （S3 S5）
  → 渲染器无从提高保真度            （S4）
  → 人审只能评「有没有」评不了「排得对不对」
  → Builder 拿不到设计意图
  → 编码期逐页重新即兴发挥          （S1 S2）
```

## 2. 设计理念（五条原则，全文一切决策的判据）

1. **设计决定必须可声明。** AI 的每一个设计判断——这块给谁看、什么数据形态、哪个按钮重要、
   一屏必须看到什么——都要有语言可以写下来。写不下来的判断等于没做。
2. **声明意图，机器算取值。** 规格层永远不出现像素、坐标、具体宽高；
   「放不放得下」由渲染与量测判定（换行是事实，不是审美）。
   已被实测证死的反例：操作列声明 `width: 220`、实际渲染 286。
3. **风格封闭，表达开放。** 框架锁死取值（色/字/距/形/影）与结构契约，
   不锁死表达形式；机检查风格合规，**永不检查「是否使用了组件」**。
   组件不是设计的单位——设计的单位是数据形态与意图，组件只是形态的一种实现（§4.3）。
4. **一切词表皆数据。** 区块、模式、控件的定义是配置文件不是渲染器代码；
   增一个词 = 增一个定义文件，闭包由单测锁死。杜绝「5 个词高保真、其余灰盒」这类
   实现内置的不对称。
5. **事实优先于审美。** 版面质量的最终裁判是运行期量测（溢出、空洞、换行、刻度），
   不是任何人的目测。量不出来的约束不进机检，也不进规范。

## 3. 架构总览

```
┌─ 设计系统真源 DS（项目级，一套）────────────────────────────┐
│  令牌三层（原始值→语义→密度档） · 版面原语 · 类契约         │
│  组件双供给（contract 级组件 + style 级类） · 受控变体       │
│  主题 = 令牌集覆盖（千业千面）                               │
└──────────────────────────────────────────────────────────────┘
                ↓ 供给（context 打包给 AI；渲染器与机检同源）
┌─ 页面设计语言 PDL（每页一份，spec 内）──────────────────────┐
│  版面结构（pattern + 带/列 + 主次/撑满） · 内容语义          │
│  （name/intent/数据形态/关键字段） · 操作语义（附着点/优先级）│
│  · 首屏承诺（fold） · 密度                                   │
└──────────────────────────────────────────────────────────────┘
   ↓ L0 确定性线框            ↓ L1 真实框架预览       ↓ L2 运行期探针
  （approve 闸门，字节一致）  （demo 态+契约 mock，   （7 探针量事实，
                               设计评审现场）          bad=0 才收口）
```

四个消费方从同一份 PDL 取数：**渲染器**（画）、**人审**（评）、**Builder**（context 切片）、
**机检**（validate / post-write / 探针）。单一真源，四处消费，零转译。

## 4. 设计系统真源（DS as Data）

### 4.1 令牌三层

```
原始值层   --raw-blue-600: #2f73c5            （只有主题文件可写）
语义层     --c-primary: var(--raw-blue-600)   （组件与页面唯一可引用层）
密度档     --sp-1..4 × density(compact|default|loose)
           表格/表单/详情各自的推荐档写进对照表
```

- 页面与组件**只许引用语义层**；原始值只存在于主题文件。
- 密度档是「刻度的语义」：36 种间距的病根不是自由，是**找不到语义档**。
  每类页面（列表/表单/详情/工作台）在对照表里有明确的推荐档。

### 4.2 版面原语（layout primitives）

把实测中页面反复自写的 grid 收编为一级结构，随框架发布、带响应式与密度：

| 原语 | 覆盖的真实形态（sustain-v3 实测的 9 个降级页全部在内） |
|---|---|
| `band` | 全宽横带（现状唯一形态） |
| `columns` | N 列分栏（两级：带 → 列，不递归） |
| `split` | 两栏主次（1fr + 定宽 sticky 侧栏） |
| `master-detail` | 左列表右详情（260px + 1fr） |
| `board` | 看板/卡片墙（auto-fill 网格） |
| `workbench` | 三列工作台（264px + 1fr + 224px 类） |

### 4.3 三层供给（组件不约束设计：形态自由，机制复用，风格强制）

> 用户裁定：**不希望 UI 组件过多约束设计。** 落实方式不是删组件，而是把
> 「功能最佳实践」从「组件的视觉形态」里剥离——这是既不丢最佳实践、
> 又不让组件站在设计上游的唯一解。

| 层 | 内容 | 强制性 |
|---|---|---|
| **风格层**：令牌 + 类契约 + 密度/受控变体 | 色/字/距/形/影的唯一来源 | **唯一强制层**——机检只查这里 |
| **行为层**（headless，无视觉形态） | 表格数据机（排序/分页/选中）、表单校验机、弹层机制（焦点圈/关闭/层叠）、上传机——以可挂到**任意标记**上的工具/组合式函数提供 | 复用不强制；**交互最佳实践住在这里，与形态解耦** |
| **成品层**：现有组件 = 行为层 + 风格层的预制组合 | VTable / VForm / 弹层等 | **可选快捷路径**——标准形态合适时最快；永不「优先」、永不被机检、在 context 里与类契约配方并列呈现 |

三条推论：

- **设计的单位是数据形态与意图（PDL 的 `shape`/`intent`），不是组件。**
  `shape: list` 可落成表格、卡片墙、时间轴；选了非标准形态时挂行为层，
  拿到同样的排序/分页/校验能力，而不是「要么用 VTable、要么重造整个数据机」。
- **受控变体**仍然成立（`density / tone / emphasis`，场景→变体对照），
  但它作用于风格层与成品层，不构成对形态的约束。
- **最佳实践的守卫换位**：冻结前靠行为层复用（机制不必重写），
  冻结后靠探针量事实（溢出/换行/交互可达）——两者都不依赖「长成组件那个样子」。

### 4.4 主题（千业千面）

- 主题 = **只含原始值层令牌**的一个文件；换行业 = 换一个文件。
- 机检三条：主题文件不得含类样式；覆盖的令牌必须已定义；语义层禁止被主题覆盖
  （主题换值不换语义）。
- 行业主题的取值由 Design MCP 在**规划期**产出、人审后固化成文件——
  一次产出，之后零 token、可 diff、可 update。

### 4.5 闭包机检（DS 的完整性由单测锁死，不设白名单）

`令牌 ↔ 类 ↔ ai-manifest ↔ 组件文档 ↔ componentMap ↔ 区块 schema` 六向闭包：
任何一处单独改动立刻红。此机制已在移动端框架验证（曾抓出「manifest 改了、样式没进去」
的半落地状态）。

## 5. 页面设计语言（PDL）

`vima:page` 的完全体。**设计声明与页面声明同块不拆文件**——拆开必然出现双真源漂移
（`layout` 与 `regions` 需要 V-SPEC-12 对账就是前车之鉴）。

### 5.1 完整示例：三列工作台（现状写不出来的页面）

```yaml
```yaml vima:page
id: PAGE-09
title: 医师工作台
menu: MENU-01
design:                                  # ← 页面级设计声明（新增）
  pattern: workbench                     # 版面模式 ∈ 模式库
  density: default                       # 页面基准密度档
  fold: [待办清单, 患者卡片]              # 首屏承诺：这些实例必须一屏可见
layout: [cards, cards, cards, table]     # 区块台账（保持既有职责：对账/计数口径）
regions:
  - columns:
      - { name: 待办,     width: 264px, blocks: [cards] }
      - { name: 主工作区, width: 1fr,   blocks: [cards], role: primary }   # 主次
      - { name: 实时指标, width: 224px, blocks: [cards], density: compact } # 局部密度
  - { blocks: [table] }
components:
  - block: cards
    name: 待办清单                        # 实例名：同词多例可分辨（渲染/对账/评审三处受益）
    intent: 医师进入后第一眼要处理的事      # 这块为什么存在（人审评的就是它）
    data: { shape: list, of: 随访待办, keyFields: [患者, 逾期天数] }
    api: GET /api/todo/list
  - block: cards
    name: 患者卡片
    intent: 当前选中患者的核心指标与快捷入口
    data: { shape: record, keyFields: [姓名, 诊断, 营养风险等级] }
    actions:                              # 操作附着点：贴本块头部行，不独占一条带
      - { type: button, label: 开处方, action: nav, target: PAGE-12, priority: primary }
      - { type: button, label: 打印,   action: api, api: POST /api/print, priority: overflow }
  - block: cards
    name: 实时指标
    intent: 治疗效果的即时反馈
    data: { shape: metrics, of: [热量达成率, 蛋白达成率, 体重趋势] }
  - block: table
    name: 本周随访记录
    api: GET /api/visit/list
    rowActions:
      - { label: 查看, action: nav, target: PAGE-08, priority: primary }
      - { label: 补录, action: modal, target: MODAL-03, priority: secondary }
      - { label: 作废, action: api, api: POST /api/visit/void, priority: overflow }
apis: [GET /api/todo/list, GET /api/visit/list, POST /api/visit/void, POST /api/print]
```
```

### 5.2 语言要素与「人类需求」的对应

用户提出的四类附加价值，逐条落到语言键上——**这就是 AI 介入的落笔处**：

| 人类需求 | 语言落点 |
|---|---|
| 内容有什么 | `name` + `intent`（每块必答「为什么存在」） |
| 什么类型的内容数据（格式与行业背景） | `data.shape ∈ list \| record \| metrics \| timeline \| chart \| freeform` + `of` + `keyFields`；行业背景由主题与模式库承接 |
| 什么样的人机交互 | `actions`（附着点）+ `priority` + 交互三种（nav/modal/api）+ 抽屉/页签加载语义（词表扩容） |
| 什么样的可读性 | `density`（页/列/块三级）+ `fold`（首屏承诺）+ `keyFields`（信息优先级）+ `role: primary`（视觉主次） |

`freeform` 是显式逃生舱：声明它必须带 `intent`，线框渲染为带说明的占位——
**诚实标注「这里是自由发挥区」，好过假装词表覆盖了一切。**

### 5.3 操作语义（细化到按钮，但不到像素）

- **附着点**：`actions` 挂在宿主块上 = 贴本块所在行（卡片头右侧 / 搜索栏行尾 / 分区标题右侧），
  不新起横带。**独立 toolbar 带只在动作 ≥4 个或页面级动作时使用**（17 页单按钮独占带 → 0）。
- **优先级**：`priority: primary | secondary | overflow`。一屏一个 primary；
  超出密度档容量（compact 2 / default 3 / loose 4）的自动收进「更多」下拉——由框架计算，
  规格只声明谁可收。
- **放不放得下**：运行期探针判定（同行元素 `offsetTop` 不一致 = 换行 = 事实），
  按声明的降级策略处理（换行 / 收 overflow / 退回独立带）。

### 5.4 校验规则（新 V-DSN 族，全部确定性）

| 规则 | 级别 | 判据 |
|---|---|---|
| V-DSN-01 | error | 业务页必须有 `design.pattern` 与 `density`；pattern ∈ 模式库 |
| V-DSN-02 | error | `regions` 铺开的区块多重集 == `layout`（吸收现 V-SPEC-12） |
| V-DSN-03 | error | 同词多例必须逐例带 `name`；`name` 页内唯一 |
| V-DSN-04 | error | `data.shape` ∈ 枚举；`freeform` 必须带 `intent` |
| V-DSN-05 | error | `actions.priority` ∈ 枚举；每页 primary ≤ 1（页级，含各块） |
| V-DSN-06 | warn | 单块行内动作 > 3 且无一个 `overflow` → 提示收纳 |
| V-DSN-07 | error | `fold` 引用的实例名必须存在 |
| V-DSN-08 | warn | `shape: list` 的块无 `keyFields` → 提示信息优先级未声明 |

## 6. 渲染与验证阶梯（三级保真，各司其职，不合并）

| 级 | 产物 | 回答什么 | 特性 | 闸门角色 |
|---|---|---|---|---|
| **L0 线框** | `render-prototype` | 有没有、对不对、**主次与密度对不对** | 零依赖、秒级、字节确定 | `approve` 前置（硬闸门） |
| **L1 真实预览** | dev server + demo 态 + 契约 mock + 画廊 | 好不好看、顺不顺手 | 需服务；产物即真实代码 | 设计评审现场（人闸门） |
| **L2 探针** | 版面冒烟 JSON 报告 | **事实**：溢出/空洞/被裁/间隙/刻度/重叠/换行 | 量化、零 LLM、按 task 归组 | `/go` 收口（`bad=0`，硬闸门） |

### 6.1 L0：schema 驱动的线框

- **每个词表词一个定义文件**（schema）：语义、数据键、线框渲染契约、componentMap、密度行为。
  渲染器读 schema 渲染，**不再内置任何词**——「5 词高保真其余灰盒」在结构上不可能复发。
- 保真度红线：**画到「三列各自可分辨、主次可见、密度可见、动作位可见」为止**。
  `shape: list` 画出 keyFields 的行、`metrics` 画出指标环位、`record` 画出字段组——
  再往上是 L1 的事。线框的价值 = 便宜 + 确定 + 可否决，推成高保真就是第二个前端框架。

### 6.2 L1：真实框架预览

- demo 态（守卫放行 + 注入 `perms:['*']` 假用户，构建期剔除）；
- **契约驱动 mock**：由契约 response 确定性生成（实测 270 接口 100% 带声明、仅 8 种类型），
  字段名与真实接口一字不差；数据量档位（空/少/多/极端长文本）是必选项——
  空列表与超长文本恰恰是暴露版面缺陷最有效的两档；
- 页面画廊 `/__gallery`：全部业务页 × 三视口 × 三态一屏看全。
- **mock 与 L2 探针共用同一套生成器与页面发现**，不做两份。

### 6.3 L2：七探针

横向溢出 / 页底空洞 / overflow 裁切 / 间隙异常 / 刻度合规 / 控件重叠 / **意外换行**（新）。
报告按 `task` 归组进修复循环（A20 同款 byTask 机制）；**探针不在场时不写空报告**——
空报告会被读成「跑过且零问题」。

## 7. AI 设计工序（规划期新增的显式一步）

位置：实体与契约就绪之后、任务拆分之前。**设计定稿了才拆任务**——
版面被否掉时不至于连带作废几十个任务文件。

```
输入（context 打包）:
  · PDL schema 与写法样例
  · 版面模式库（每 kind 6–8 个模式：何时用 + 骨架 PDL + 反例）
  · 数据形态提示：从契约自动推导（response 字段数/类型 → 建议 shape 与 keyFields 候选）
  · 行业上下文（spec 第一章 + 主题）
过程（AI 逐页回答五问，答案直接落 PDL 键）:
  ① 这一页内容有什么？→ blocks + name + intent
  ② 数据是什么形态？   → data.shape / of / keyFields
  ③ 谁在什么场景读？   → density + pattern
  ④ 最高频交互是什么、放哪？→ actions + priority + 附着点
  ⑤ 一屏必须看到什么？ → fold
输出: PDL 声明（不是代码、不是散文）
评审: L0 渲染 → 人审「设计判断」（intent 对不对、主次对不对、首屏承诺对不对）
     → 通过后 PDL 冻结为设计真源，进任务拆分
```

**AI 的边界**：判断层（该贴哪、谁重要、什么形态）全权交给 AI；
取值层（多宽、放不放得下、收几个）全权交给框架与探针。AI 不写像素，不绕过 PDL 写自由 CSS。

## 8. 机检体系（执行者阶梯落位）

## 11. 不做（每条都有代价论证）

- **不做像素/坐标级设计声明**（D-DF-05）。
- **不做自动布局算法**（让 AI/算法自行决定几栏谁撑满）——版面意图由人审冻结，
  机器只渲染与守卫；把决定权交还概率行为正是「没有灵魂」的成因。
- **不做高保真线框**（§6.1 红线）。
- **不做运行时 Design MCP**——它进规划期产 PDL 与主题，产物固化为仓库文件。
- **不做截图 diff 闸门**——多端×多视口下噪声不可持续；探针量化 + bad>0 才升级到截图。
- **不做递归嵌套 regions**——两级（带→列）已覆盖 9 个实测多列页全部形态；
  更复杂结构走版面模式（原语组合），不走嵌套。
- **不做组件使用率指标**——要量的是风格一致性，不是组件覆盖率。
- **不做「每行业一套框架 dist」**——一套框架 + N 个令牌主题；N 套 dist = N 份漂移
  （vendor 分叉的亏已吃过）。

## 12. 质量保证总链 —— 与 Claude Design 的确切位置

> 回答两问：Claude Design 能否起作用？「整体设计质量」与「设计的高质量落地」各由什么保证？
> Claude Design 的能力面经工具逐一核实（起稿 / 设计技能 / 预览探测 / 钉针评论回路），非推断。

### 12.1 Claude Design 的三个角色（能起作用，且位置明确）

| 角色 | 用它的什么能力 | 产出 → 固化为仓库内的什么 |
|---|---|---|
| **R1 行业视觉语言生产**（千业千面的取值来源） | `hifi-design` / `frontend-design` 两个设计质量技能 + 真实 HTML 起稿 + 设计系统绑定 | **主题令牌文件（原始值层）**——人审定稿后由 AI 提取取值写成 `themes/<行业>.css` |
| **R2 版面模式库孵化**（一次性投入） | 同上，逐模式起稿参考页 | **模式库条目**：每 kind 6–8 个 pattern 的骨架 PDL + 何时用/反例，进模板资产 |
| **R3 难页设计草案 + 钉针评审回路** | `write_files` 起稿 → 用户在页面元素上**钉针评论** →「Send to Claude」入队 → `list_comments` 读取 → 改稿 → `ack_comments` 清账 | **设计判断回填 PDL**（intent / 主次 / fold / priority）；草案本身不进仓库 |

两个此前低估的能力，恰好补上工序里最缺的两块：

1. **设计期 Agent 有眼睛**：`render_preview` 返回可供浏览器工具访问的预览地址，
   Agent 在起稿过程中能**自己截图、量 DOM**——设计迭代不再盲画。
2. **钉针评论是结构化人审通道**：意见钉在具体元素上（不是聊天里的散文描述），
   带作者校验（`author_is_you`，防第三方指令注入）与队列语义（读 → 处理 → ack，处理完才清账）。
   **人审「这个按钮太挤 / 这列该宽」这类元素级意见，精确度比口头转述高一个量级。**

### 12.2 两条硬边界（越界即坏）

1. **云端产物不是真源。** Claude Design 是登录态云服务、预览链接短时效、产出非字节确定
   ——因此**不进运行时、不做任何闸门**；R1–R3 的一切产出必须固化为仓库文件
   （主题令牌 / 模式库 / PDL 声明）。云端项目是草稿纸，仓库文件才是产物。
2. **草案 ≠ 实现，美学保真不靠「照着草案抄」。** 落地页面的观感与草案一致，
   机制是**结构性等价**——两者用同一套 DS（同令牌、同类、同变体），而不是像素比对。
   所以草案的职责是**定判断与取值**，不是定每一像素；草案里超出 DS 的视觉手法，
   正确路径是「收编进 DS」（新增原语/变体，走真源），不是页面私有样式。

### 12.3 整体设计质量：五道保证（从源头到评审）

| # | 机制 | 挡住什么 |
|---|---|---|
| ① | **语言强制思考**：V-DSN 族——无 `intent`/`shape`/`fold`/`pattern` 过不了 validate | 「没想清楚就开写」——写不下来的判断等于没做 |
| ② | **证据供给**：契约推导 data-shape、模式库、行业上下文进 context | 凭空设计——从零即兴正是凌乱之源 |
| ③ | **探索空间**：R1–R3（设计技能 + 起稿 + 自查预览） | 第一稿即终稿、无迭代 |
| ④ | **人审对象 = 设计判断**：在 L0 渲染稿上评 intent/主次/首屏，钉针评论承接元素级意见 | 人力花在机器能查的事上；意见转述失真 |
| ⑤ | **一致性结构化**：DS 六向闭包 + 受控变体 | 跨页风格漂移——一致靠机制不靠自觉 |

### 12.4 设计的高质量落地：五道保证（从冻结到回修）

| # | 机制 | 挡住什么 |
|---|---|---|
| ① | **PDL 冻结 + context 切片直达 Builder** | 二次转译失真——Builder 拿到的就是评审通过的那份声明 |
| ② | **框架吸收机制难点**（版面原语/密度/溢出收纳/自动宽度 + 行为层的数据机/校验机/弹层机制） | Builder 写错——机制不是它写的就不会错；**形态仍归它按 PDL 自由落** |
| ③ | **写入时机检**（post-write：结构标记对账 L0 manifest + 风格合规） | 落盘即偏——错误活不过一次写入 |
| ④ | **运行期事实**：七探针，`bad = 0` 才收口 | 「看起来对」——溢出/空洞/换行是量出来的 |
| ⑤ | **Verifier 逐任务点验收 + byTask 回修循环** | 漏做与做废——问题派回原任务，闭环到修完 |

### 12.5 总链一图

```
 Claude Design(R1/R2/R3)      五问设计工序
        └──────────┬──────────────┘
                   ▼
     PDL + 主题 + 模式库（仓库文件 = 真源）
                   ▼  L0 线框渲染（字节确定）
          人审设计判断 ←→ 钉针评论回路          【设计质量在此定格】
                   ▼  approve 冻结
       context 切片 → Builder 实现
                   ▼  post-write 写入时机检
       L1 真实预览（demo+契约 mock）→ 人查观感
                   ▼  L2 七探针  bad=0
          converge 收口 ←── byTask 回修          【落地质量在此收口】
```

一句话：**设计质量由「语言强制 + 证据 + 评审」在冻结前保证；落地质量由
「同源供给 + 框架吸收 + 三层机检」在冻结后保证。Claude Design 工作在冻结之前，
产物全部固化进仓库；冻结之后没有它，也不需要它。**

### 13.1 既有 UI 框架的处置：不推翻，收编 + 补层 + 分级

形态自由与机制复用两全（D-DF-11）。库侧两件大活：令牌化收敛 + 行为层抽取。
